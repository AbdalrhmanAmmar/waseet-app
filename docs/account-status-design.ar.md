# شاشة مراجعة الحساب

تحديث لاحق: أصبح للحساب المرفوض تصميم مستقل موثّق في [تقرير شاشة عدم الموافقة](account-rejection-design.ar.md)، مع الرسمة الجديدة وسبب الرفض الاختياري والدعم كإجراء أساسي. شاشة Pending الموضحة هنا تظل مخصصة للحساب قيد المراجعة.

تم تنفيذ شاشة الحساب المعلّق اعتمادًا على المعاينة المعتمدة، مع رسمة الحساب والساعة وشعار وسيط والألوان الخضراء والبرتقالية والخلفية الفاتحة.

- النصوص والمراحل والأزرار عناصر React Native فعلية؛ اسم الترحيب يأتي من الحساب.
- الرسمة أصل محلي شفاف في `assets/images/account-review.png`، مستخرج باستخدام imagegen من المعاينة. قد تختلف تفاصيل الرسم الدقيقة قليلًا عن الصورة المولّدة الأصلية.
- مراحل التفعيل: إنشاء الحساب، مراجعة البيانات، تفعيل الحساب، مع رموز وخط اتصال كما في التصميم.
- زر «تحديث حالة الحساب» يجلب ملف المستخدم من الخادم ويعرض التحميل والنتيجة أو رسالة خطأ قابلة لإعادة المحاولة، ويمنع تكرار الطلب أثناء تنفيذه.
- تُراجع الحالة عند رجوع التطبيق للمقدمة أو استعادة تركيز نافذة الويب. عند وصول حالة مفعّلة تتولى حماية المسارات الانتقال لمساحة الدور الصحيح.
- الدعم متاح داخل نافذة من الشاشة نفسها، حتى للحساب المعلّق. يستخدم وسائل التواصل الموجودة في `src/config/contact.ts` ولا يفتحها إلا عند ضغط المستخدم عليها.
- الحسابات المرفوضة والموقوفة وغير المفعّلة لها نصوص مخصصة بدل وصفها بأنها قيد المراجعة.
- الشاشة قابلة للتمرير على الهواتف الصغيرة ومع تكبير الخط، وتحترم المساحات الآمنة. شريط النظام والساعة يعرضهما الجهاز نفسه ولا يتم رسم ساعة وهمية داخل التطبيق.

## التنظيم

- `src/app/account-status.tsx`: ربط المسار بالشاشة فقط.
- `src/screens/shared/AccountStatusScreen/index.tsx`: واجهة الشاشة.
- `src/components/shared/account/ActivationSteps.tsx`: مراحل التفعيل.
- `src/components/shared/account/SupportSheet.tsx`: خيارات الدعم.
- `src/hooks/shared/use-account-status.ts`: تحديث الحالة ودورة حياة التطبيق.
- `src/auth/account-status.ts`: المحتوى حسب حالة الحساب.

## التحقق

نجح TypeScript وESLint والتنسيق و12 اختبار وحدات وتصدير Web وiOS وAndroid. أضيفت 9 حالات اختبار للواجهة تشمل التفعيل للأدوار الأربعة، الخطأ وإعادة المحاولة والدعم والخروج على عرض 320px، التحديث عند العودة، وحالات الرفض والإيقاف وعدم التفعيل. مجموع اختبارات الواجهة 22 سيناريو.

اختبارات المتصفح تستخدم API وهميًا، ولا تنشئ حسابات أو تغيّر حالة مستخدم على الخادم الحقيقي. لا تعني عملية التصدير بناء إصدار متجر أو اختبار جميع الأجهزة فعليًا.

## إصلاح رفض تسجيل الدخول للحساب المعلّق

كانت النسخة الأولى تعرض شاشة الحالة عندما ينجح الدخول ويعيد الخادم جلسة بحالة Pending فقط. إذا رفض `Auth/login` الطلب برسالة مثل `Your account is pending approval`، كانت الرسالة تظهر داخل نموذج الدخول.

أصبح نموذج الدخول يعرض نفس شاشة المراجعة عند وصول رسالة صريحة بأن الحساب قيد المراجعة، حتى لو لم يمنح الخادم token. هذه واجهة توضيحية داخل مسار الدخول وليست جلسة مصادقة: لا يتم اختلاق معرف مستخدم أو دور أو token، ولا تُطلب بيانات محمية. تُمسح كلمة المرور من النموذج، ويظل الدعم متاحًا. زر «إعادة تسجيل الدخول» يرجع للنموذج للتحقق من التفعيل بالمصادقة الصحيحة، بدل الادعاء بتحديث ملف مستخدم غير مسجل.

أما الجلسات الفعلية بحالة Pending فتبقى على مسار `/account-status` مع تحديث الملف والانتقال التلقائي بعد التفعيل كما سبق. اختبارات الإصلاح تغطي رفض الدخول عبر HTTP 200 مع `isSuccess: false`، و401 و403، ثم إعادة الدخول بعد التفعيل. أخطاء كلمة المرور والاتصال العادية تبقى أخطاء داخل النموذج.
