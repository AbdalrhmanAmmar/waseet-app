# تقسيم الطلبات وحالات التوصيل

تستخدم صفحات التاجر والمبيعات والإدارة والمندوب مكونات مشتركة لاختيار «الكل / داخلي / خارجي» وعرض الحالات وترجمتها.

- يحدد `deliveryMode` النوع أولًا؛ عند غيابه تستخدم منطقة التوصيل. البيانات غير الكافية تبقى «غير محدد» وتظهر في الكل.
- `status` حالة الطلب المحلية دائمًا. `oliveryStatus` حالة الشحنة الخارجية ولا تستبدل بـ `deliveryStatus`.
- فلتر الخارجي يستخدم حالة الشحنة، وله مجموعة إضافية مستقلة للحالة المحلية. الداخلي والكل يفلتران بالحالة المحلية. يمكن اختيار عدة حالات والبحث بالعربية أو كود الحالة. تغيير نوع التوصيل يمسح الحالات المختارة.
- القاموس المشترك يغطي جدول الحالات المقدم، بما فيه اختلاف ترجمة المرتجعات حسب المصدر والفرق بين `Ready for Dispatch` و`ready_for_dispatch`. `printing_waiting` مميزة عن `waiting_printed`. الكود غير المعروف يظهر بنصه ولون محايد.
- أكواد الخادم لا تتغير. القواميس مسؤولة عن العرض ولا تمنح صلاحيات أو انتقالات جديدة. محرك تغيير الحالة والآثار المالية ليس جزءًا من تغيير صفحة القائمة هذا.
- الأعداد والبحث والفلاتر محلية للطلبات المحملة؛ صفحات التاجر والمبيعات تحتفظ بالتحميل المتدرج وزر صريح لتحميل المزيد، والإدارة والمندوب يحتفظان بتحميل بقية الصفحات الموجود.
- لا تظهر الحالات الطويلة داخل حاوية ذات ارتفاع ثابت، وتلتف لتناسب الشاشات الصغيرة.

التحقق: اختبارات وحدة لفصل المصادر والترجمات وتحديد النوع، واختبارات واجهة للأدوار الأربعة بعرض 320 بكسل عبر API محاكى. لم تنفذ تغييرات على طلبات حقيقية.
