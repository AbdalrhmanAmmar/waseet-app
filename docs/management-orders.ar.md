# صفحة طلبات الإدارة

تستخدم صفحة `ManagementEmployee` التصميم المشترك مع الديلفري: الترحيب، ملخص الطلبات، البحث، فلاتر الحالات، بطاقات الطلبات ونافذة تحديث الحالة بمراجعة قبل الحفظ.

## البيانات والصلاحيات

- مصدر الإدارة بقي `GET /api/orders?page=...&pageSize=20` عبر `useManagementOrdersQuery`، وليس `orders/my-deliveries`.
- المصدر الخاص بالديلفري بقي `GET /api/orders/my-deliveries`.
- تحديث حالة الإدارة يمر عبر `managementOrderStatus`: `POST orders/{id}/status` مع `targetStatus` و`note` عند وجود ملاحظة.
- لا تُضاف صلاحية إنشاء الطلب أو عرض أرباح إلى موظف الإدارة.

## العرض والسلوك

- تبدأ الصفحة بفلتر «تحتاج متابعة»، الذي يشمل الحالات غير النهائية بحسب تعريفات الخادم مع القيم الاحتياطية الحالية.
- الملخص يعرض إجمالي الطلبات المحمّلة والطلبات المحتاجة للمتابعة. يُذكر صراحة إن كانت الأعداد والبحث لا يشملان كل الصفحات بعد.
- البحث بالرقم والاسم والهاتف والمنطقة يدعم الأرقام العربية وتطبيع النص العربي.
- بطاقة الإدارة تعرض الحالة والعميل والمنطقة والعنوان وتاريخ الطلب الصالح عند إرساله من الخادم، والاتصال وتحديث الحالة. لا يظهر زر الخريطة في قائمة الإدارة.
- الضغط على البطاقة يفتح تفاصيل الطلب، ومن التفاصيل تُستخدم نفس نافذة مراجعة تحديث الحالة.
- تُحدث بيانات الطلب وتعريفات الحالات عند فتح النافذة. الحالة النهائية تمنع التعديل؛ تعثر الطلب يتطلب سببًا؛ الخادم يحسم صلاحية الانتقال.
- الحفظ يتطلب مراجعة ثم تأكيدًا، ويمنع التكرار ويحافظ على الاختيار والملاحظات عند رفض الخادم.
- تحميل بقية الصفحات يتم بالتتابع أثناء تركيز الشاشة. الفشل يوقف المحاولات التلقائية، وإعادة المحاولة تستأنف الصفحة الفاشلة مع الاحتفاظ بالطلبات السابقة.

## التنظيم

المكونات المشتركة في `src/components/shared/orders`: `OrdersWorkspace` و`WorkspaceOrderCard` و`OrderStatusSheet` و`workspace-styles`. التصفية والروابط في `src/domain/order-workspace.ts`، وتحميل الصفحات في `src/hooks/shared/use-order-workspace.ts`. لكل دور hook ونافذة ربط mutation خاصة به، فلا تعتمد الإدارة على API الديلفري.

## التحقق

اختبارات واجهة بمحاكاة الخادم تغطي استعمال `orders` حصريًا للإدارة، إضافة Bearer، البحث والفلاتر والتفاصيل، تحديث الحالة بعد التأكيد، التعثر ورفض الحفظ، الحالة النهائية، فشل صفحة لاحقة واستئنافها، والتمييز بين الخطأ والقائمة الفارغة. تُشغّل اختبارات الديلفري أيضًا للتحقق من استمرار سلوكه بعد استخراج المكونات المشتركة. لم تُرسل تغييرات إلى طلبات الإنتاج.

النتيجة: نجحت TypeScript وESLint والتنسيق، و30 اختبار وحدة، و21 اختبار واجهة (6 للإدارة، 6 للديلفري، و9 للأدوار). نجح تصدير Expo للويب وiOS وAndroid. لقطات بيانات الاختبار: [صفحة الإدارة](redesign-preview/management-orders.png)، [تأكيد الحالة](redesign-preview/management-confirm.png)، [عرض 320px](redesign-preview/management-320.png).
