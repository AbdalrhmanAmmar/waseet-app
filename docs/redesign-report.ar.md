# تقرير إعادة تصميم تطبيق وسيط

> تحديث: هذا التقرير يوثّق مرحلة سابقة. أُلغيت السلة ومسار الشراء، وحل محلهما إنشاء الطلب المباشر مع لون إلزامي لكل منتج. راجع [تقرير إنشاء الطلب](order-create-design.ar.md) للسلوك الحالي.

التاريخ: 18 سبتمبر 2026.

تم تحديث واجهات التطبيق لتتبع هوية شعار وسيط المستخدم في Dashboard، مع إعادة بناء رحلة إنشاء الحساب وتوحيد المكونات المشتركة للأدوار الأربعة.

## إنشاء الحساب

- إزالة حقل رقم هاتف أوليفر من التسجيل ومن التحقق ومن البيانات المرسلة عند إنشاء الحساب. رقم الهاتف الأساسي ما زال مطلوبًا للتواصل.
- تقسيم التسجيل إلى ثلاث خطوات: نوع الحساب والبيانات الشخصية، التواصل والعنوان، ثم مراجعة البيانات وكلمة المرور.
- عرض الأدوار الأربعة ببطاقات واضحة: تاجر، موظف مبيعات، موظف إدارة، مندوب توصيل.
- حفظ المدخلات عند الرجوع بين الخطوات، مع مؤشر للخطوة الحالية وأزرار متابعة ورجوع ثابتة.
- إبقاء تاريخ الميلاد فارغًا حتى يؤكده المستخدم. رفض التواريخ المستقبلية والتواريخ غير الموجودة مثل 31 فبراير، مع دعم السنوات الكبيسة.
- إظهار مدينة التوصيل لمندوب التوصيل فقط، وإتاحة اختيارها من مناطق الخادم أو إدخالها عند تعذر تحميلها.
- التحقق من الحقول قبل الانتقال، وإظهار أخطاء واضحة بالعربية، وإظهار/إخفاء كلمات المرور.
- منع إرسال التسجيل مرتين أثناء معالجة الطلب. عند رفض الخادم تُحفظ المدخلات وتظهر رسالة الخطأ، وعند النجاح تظهر شاشة تأكيد مع زر تسجيل الدخول.
- لا يغيّر هذا التعديل بيانات أوليفر الموجودة مسبقًا في حسابات الخادم؛ قد تظهر في الملف الشخصي إذا أعادها الخادم.

## الهوية والتصميم

- اعتماد الأخضر `#147D64` للأفعال الرئيسية، والأخضر الداكن `#103E32` للمساحات البارزة، والبرتقالي `#F29A4A` كلون مساعد.
- إضافة خط Tajawal محليًا بأوزان Regular وMedium وBold مع ملف ترخيص OFL، وتحديث الخطوط المستخدمة في الواجهات.
- إنشاء `src/theme/tokens.ts` للألوان والخطوط والمسافات والحواف، وتحديث ثيم الشاشات المنقولة ليتوافق معه.
- إنشاء مكونات مشتركة للأزرار والبطاقات والشعار وعناوين الأقسام، وتخطيط موحد لشاشات المصادقة.
- تحسين حالات التحميل والخطأ والفراغ وإعادة المحاولة، وحالات التركيز والخطأ في الحقول، وتسميات الأزرار لقارئات الشاشة.
- احترام إعداد تقليل الحركة في الحركات الزخرفية والنوافذ التي تم تحديثها.

## الشاشات التي تغيرت

| الشاشة | التغيير |
| --- | --- |
| المقدمة | محتوى عربي ورسومات تعتمد على الشعار المحلي بدل الصور الخارجية |
| تسجيل الدخول | عنوان واضح، نموذج مرتب، أخطاء الخادم داخل الشاشة، إظهار كلمة المرور |
| الرئيسية | ترحيب حسب الحساب، ملخص الرصيد/المبيعات، إحصاءات من الخادم، منتجات وآخر الطلبات |
| المنتجات | بطاقات جديدة، بديل للصورة عند غيابها أو فشلها، حالة نفاد المخزون وأزرار مستقلة للإضافة والتفاصيل |
| تفاصيل المنتج | إبراز السعر والمخزون والوصف، سعر التاجر عند توفره، وأزرار السلة والكميات |
| السلة | بطاقات للمنتجات، تعديل سعر البيع، حدود الكمية حسب المخزون، وإجمالي واضح |
| إتمام الطلب | تنسيق موحد لبيانات العميل ومنطقة التوصيل والدفع والملخص، وتحسين التعامل مع لوحة المفاتيح |
| الطلبات والتفاصيل | بطاقات للحالة والعميل والقيمة، ملخص تفصيلي وأفعال حسب الدور |
| تتبع الطلب | بطاقات للسجل والحالة والملاحظات والتاريخ وزر اتصال عند توفر رقم المندوب |
| الحساب والقائمة | ملف شخصي منظم، بطاقة الرصيد للتاجر، تعديل البيانات والتواصل والخروج |
| حالة الحساب والدعم | تنسيق متسق مع الهوية للشاشات المشتركة |

تم الاحتفاظ بفصل `components` و`api` و`hooks` حسب الدور، مع وضع التصميم القابل لإعادة الاستخدام في `shared`. لم تتغير عناوين API أو قواعد صلاحيات الأدوار بسبب إعادة التصميم. لا تُعرض أرصدة أو طلبات مصطنعة عندما لا يوفرها الخادم.

## التحقق

- فحص TypeScript وESLint وتنسيق Prettier.
- 12 اختبارًا لوحدات التطبيق وعقد الطلبات، تشمل تاريخ الميلاد وصحة التسجيل دون أوليفر.
- 13 سيناريو واجهة باستخدام Chromium بحجم هاتف: التسجيل ومراجعة البيانات وفشل الخادم وإعادة المحاولة، متطلبات مندوب التوصيل، الدخول للأدوار الأربعة، حماية المسارات، إنشاء الطلب وتفريغ السلة، تفاصيل المنتج والحساب، وشاشة دخول بعرض 320px.
- مراجعة لقطات من الواجهات، وإصلاح حجم نافذة تاريخ الميلاد على الويب وقص أسماء التبويبات الذي ظهر أثناء المراجعة.
- تصدير حزم Expo للويب وiOS وAndroid.
- فتح شاشة التسجيل المعدلة في Expo Go على محاكي iOS ومراجعتها بصريًا.

اختبارات الواجهة تعترض API ببيانات اختبار محلية. لم تُنشأ حسابات أو طلبات حقيقية على الخادم. فحص iOS بصري لشاشة التسجيل، وليس اختبارًا آليًا لكل رحلة على iOS. لم يُشغّل محاكي Android ولم يُبن إصدار متجر موقّع ضمن إعادة التصميم.

## المعاينة والتشغيل

صور المراجعة موجودة في [مجلد المعاينات](redesign-preview/). تعرض صور الحساب والمنتجات بيانات اختبار.

للتجربة باستخدام Expo Go:

```sh
npm start
```

إذا ظلت جلسة Metro القديمة تعرض التصميم السابق، أعد تشغيلها مع تنظيف الكاش:

```sh
npm start -- --clear
```

التغييرات داخل الشاشات يمكن معاينتها في Expo Go. إعداد أيقونة التطبيق وشاشة البداية النهائية موثّق بشكل مستقل في [دليل الهوية](branding.md).
