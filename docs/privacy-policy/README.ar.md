# سياسة خصوصية وسيط

## الملف الذي ترفعه

`privacy-policy.html` هو الملف النهائي المستقل: HTML عربي RTL، وتنسيقات Tailwind مبنية ومضمّنة، وJavaScript لتحسين التصفح والطباعة ونسخ البريد. الشعار وخط Tajawal وترخيصه مضمّنة. لا يحتاج الملف إلى CDN أو ملفات صور أو خطوط أخرى، ويظل المحتوى وروابط التواصل والحذف متاحًا بدون JavaScript.

اعتمدت الصفحة اسم الجهة **الوسيط الذكي** والبريد **abdammar2023@gmail.com** بناءً على اختيار صاحب التطبيق. تاريخ النسخة 20 سبتمبر 2026؛ حدّثه عند تعديل السياسة فعليًا.

## قبل الإرسال إلى Google Play

1. راجع السياسة مع المسؤول عن الخادم والتشغيل قبل نشرها: خصوصًا الجهات المستلمة للبيانات، السجلات التقنية، النسخ الاحتياطية، وممارسات الحذف والاحتفاظ. مراجعة كود الهاتف لا تثبت ممارسات الخادم أو مزودي الخدمة.
2. صاحب التطبيق لم يحدد مدة معتمدة للاحتفاظ أو لمعالجة طلب الحذف. لذلك تعتمد الصياغة على أغراض الاحتفاظ ومعاييره ولا تخترع عدد أيام. يجب تحويل ذلك إلى إجراء فعلي، وتحديد مدد الفئات والاستثناءات عند اعتمادها وتحديث السياسة وفقها.
3. طلب الحذف عبر الصفحة يفتح البريد فقط. يجب متابعة البريد فعليًا، والتحقق من صاحب الطلب، وتنفيذ حذف الحساب والبيانات غير المستثناة على الخادم وعند المعالجين المعنيين، وإبلاغ صاحب الطلب بالنتيجة والاستثناءات. لم يُضف بهذا العمل API لحذف الحساب ولم تُختبر عملية حذف على الخادم.
4. ارفع **الملف النهائي وحده** إلى استضافة عامة عبر HTTPS. يمكن تسميته `index.html` في مجلد `privacy`. لا تنشر ملفات المصدر أو هذا الدليل باعتبارها السياسة.
5. افتح الرابط دون تسجيل دخول ومن الهاتف. يجب أن يعرض HTML مباشرة، وليس صفحة GitHub لعرض الكود أو ملف PDF، وألا يكون محجوبًا جغرافيًا.
6. ضع الرابط في خانة سياسة الخصوصية في Play Console. يمكن استخدام رابط الصفحة نفسه مع `#delete-account` للوصول مباشرة إلى قسم طلب الحذف، بعد التأكد أن الاستضافة تحفظ هذا المسار وأن القسم متاح دون حساب.
7. أضف رابط السياسة ومسارًا واضحًا لطلب حذف الحساب داخل التطبيق، مثل صفحة «حسابي». يتطلب الربط عنوان الاستضافة النهائي؛ لم يُخترع رابط أو يُعدّل التطبيق في هذه المهمة.
8. أكمل نموذج Data safety بناءً على النسخة النهائية وممارسات الخادم وSDKs، وطابق اسم التطبيق/الجهة مع صفحة المتجر. وجود ملف سياسة وحده لا يضمن قبول التطبيق.

## أساس الصياغة وحدود المراجعة

| الموضوع | المصدر في المشروع |
| --- | --- |
| بيانات التسجيل وتاريخ الميلاد والعنوان | `src/schemas/auth.ts`، `src/screens/auth/SignUp/index.tsx` |
| الحسابات والأرصدة وبيانات العميل والطلب | `src/types/models.ts` |
| HTTPS وواجهة الخادم الحالية | `src/config/env.ts`، `src/api/client.ts` |
| حفظ رمز الجلسة ونسخة الحساب وتسجيل الخروج | `src/services/storage.ts` |
| إشعارات اختيارية مشروطة بإعداد الخادم | `src/services/notifications.ts` |
| التوصيل الداخلي والخارجي | `src/domain/order-workflow.ts`، `docs/order-workflow.ar.md` |
| مستند الطلب والمشاركة | `src/components/shared/orders/OrderWaybill.tsx` |

تعامل السياسة الإشعارات بوصفها ميزة مشروطة بالتفعيل والإذن، ولا تفترض تفعيلها في كل بناء. لا تزعم تشفير جميع بيانات الخادم أو اعتمادًا أمنيًا أو إقامة البيانات في بلد محدد. لم تُنشر الصفحة على استضافة ولم تُرسل رسائل بريد نيابةً عن صاحب التطبيق.

## تعديل الصفحة وإعادة البناء

عدّل `source.html` للنص والتخطيط، و`style.css` للتنسيقات، و`enhance.js` للتفاعلات. ثم شغّل من جذر المشروع، بعد تثبيت أدوات البناء في مجلد مؤقت:

```sh
npm install --prefix /tmp/waseet-privacy-build --no-audit --no-fund tailwindcss@4.3.3 @tailwindcss/cli@4.3.3
node docs/privacy-policy/build.mjs /tmp/waseet-privacy-build/node_modules/@tailwindcss/cli/dist/index.mjs
```

هذه أدوات بناء فقط؛ لا تضيف مكتبات إلى تطبيق Expo. لا تعدّل الملف الناتج ثم تعيد البناء، لأن التعديل سيُستبدل بمحتوى المصدر.

## التحقق المنفذ

فُحص الملف الناتج باستخدام Chromium/Playwright بعروض 320 و390 و768 و1440 بكسل دون تجاوز أفقي، مع مراجعة لقطتي الهاتف والكمبيوتر. نجحت روابط الأقسام، ورابط البريد لطلب الحذف، وزر الطباعة، وحالتا نجاح نسخ البريد وتعذره. اختُبرت قراءة الأقسام والتنقل إلى الحذف مع تعطيل JavaScript. لم تظهر أخطاء JavaScript أو طلبات HTTP خارجية أثناء العرض. لم يرسل الفحص بريدًا أو يحذف حسابًا، ولم يتحقق من وصول الرسائل إلى البريد.
