# تصميم صفحة المنتجات — واجهة عاجية وأخضر زمردي

تم تطبيق التصميم المعتمد بمكونات React Native فعلية، مشتركة بين التاجر وموظف المبيعات. الصور والمنتجات والأسعار في الصورة المرجعية توضيحية؛ التطبيق يعرض بيانات API الفعلية ويستخدم شعار وسيط الأصلي وخط Tajawal.

## ما تغير

- هيدر مختصر بعنوان «المنتجات» وعدد المنتجات المحمّلة، مع شعار وسيط ومفتاح الشبكة والقائمة في الأعلى.
- خلفية عاجية `#F7F5F1`، بطاقات بيضاء، أخضر داكن `#14594C`، ولمسة شامبين لعناوين التصنيفات. الألوان محصورة في الكتالوج والفلاتر.
- بحث بالاسم أو الكود، زر فلاتر أبيض مع عدد الفلاتر النشطة، وتصنيفات بحواف مستديرة مستمدة من البيانات. لا يظهر تصنيف «عام» مفترض عندما لا يرسل الخادم تصنيفًا.
- صف للنتائج والترتيب؛ زر «ترتيب المنتجات» يفتح لوحة التصفية والترتيب نفسها. يمكن إزالة الفلاتر منفردة.
- صور مربعة أكبر بحواف مستديرة، مع الحفاظ على الصورة كاملة دون قصها. عند فشل الصورة يظهر بديل صريح «الصورة غير متاحة».
- البطاقة توضح التصنيف والاسم والكود وسعر البيع أو سعر البيع المقترح حسب البيانات. الأسعار بمنزلتين عشريتين مع USD، والقيمة الصفرية الصحيحة تظهر كما هي.
- سعر التاجر يظهر للتاجر فقط إذا أرسله الخادم بقيمة صالحة. لا يوجد هامش ربح محسوب أو سعر افتراضي.
- المخزون يظهر فوق زر الطلب؛ «نفدت الكمية» عند نفاد مخزون معلوم، و«التوفر غير محدد» عند غياب معلومة المخزون. زر الإنشاء معطل في الحالتين.
- زر «إنشاء طلب» بخلفية خضراء فاتحة وحدّ أخضر، يفتح مسار الطلب الحالي مع المنتج. الضغط على بيانات البطاقة يفتح التفاصيل. لا توجد سلة.
- لوحة الفلاتر تتبع الألوان نفسها: التصنيف، المتوفر فقط، نطاق السعر والترتيب. تبقى التعديلات مسودة حتى «تطبيق»، والإغلاق يلغيها. الأرقام العربية والتحقق من النطاق محفوظان.

## التجاوب وسهولة الاستخدام

الشبكة عمودان على الهاتف وثلاثة عند عرض 740 فأكثر. أقل من 350 أو عند تكبير الخط فوق 1.25 يتحول المحتوى إلى قائمة لتجنب ضغط النص. في القائمة تكون الصورة بجانب المعلومات، وعند تكبير الخط تنتقل فوقها. اختيار العرض محفوظ محليًا، والبحث والفلاتر محفوظان أثناء زيارة التفاصيل والعودة.

البحث والتصنيفات ثابتان أثناء التمرير، مع مراعاة المساحات الآمنة أعلى الشاشة وجانبيها. عناصر التحكم الأساسية لا تقل عن 44 نقطة، ولها أسماء وصول وحالات اختيار وتعطيل. لوحة الفلاتر تحترم تقليل الحركة. يبقى شريط التنقل الحالي، ويمكن تمرير آخر منتج فوقه للوصول إلى زر الطلب.

## بيانات الخادم وحالات التحميل

لم يتغير عنوان API ولا التفويض ولا مسار إنشاء الطلب. كتالوج التاجر يستعمل `GET /api/Product/all` فقط، والتفاصيل تستعمل `GET /api/Product/{id}`. لا استدعاء لقوائم الأسعار أو مصادر إضافية للأسعار.

تستمر الصفحات في التحميل بالتتابع أثناء فتح الكتالوج. العدد أثناء التحميل أو الفشل يوضح أنه ضمن البيانات المحملة، والبحث الشامل لا يُعلن اكتماله قبل انتهاء الصفحات. تبقى حالات التحميل الأولي، والكتالوج الفارغ، والبحث بلا نتائج، والفشل الأولي، والفشل الجزئي مع إعادة المحاولة منفصلة.

## الملفات

- `src/screens/shared/ProductsScreen/index.tsx`: الهيدر والبحث والتصنيفات والترتيب وربط القائمة.
- `src/screens/shared/ProductsScreen/styles.ts`: المسافات والتخطيط والتجاوب.
- `src/components/shared/catalog/CatalogProductCard.tsx`: تصميم البطاقة والبيانات وحالات التوفر.
- `src/components/shared/catalog/catalog-theme.ts`: ألوان الكتالوج المشتركة.
- `src/components/shared/catalog/CatalogFilters.tsx`: تنسيق لوحة الفلاتر.
- `tests/e2e/catalog.spec.ts`: سيناريوهات الكتالوج والأسعار والصلاحيات والتجاوب والبيانات الناقصة.

## التحقق والمعاينات

نجحت فحوص TypeScript وESLint وPrettier وGit diff، و26 اختبار وحدة، و13 سيناريو واجهة للكتالوج والتفاصيل، وتصدير Web وiOS وAndroid. تغطي اختبارات الكتالوج البحث عبر الصفحات، الفلاتر والترتيب، صلاحية سعر التاجر، إنشاء الطلب والعودة من التفاصيل، الفشل والتعافي، والمخزون المفقود والصورة المعطوبة والسعر الصفري والعرض عند 320 و390 و768.

تستخدم اختبارات الواجهة API محاكى ولا تنشئ طلبات على الخادم الحقيقي. صور المعاينات التالية من التطبيق نفسه ببيانات اختبار بلا صور منتجات، لذلك يظهر بديل الصورة المفقودة. عند إرسال الخادم صورًا صالحة تظهر مكانه تلقائيًا.
