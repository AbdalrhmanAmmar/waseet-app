# تقرير نقل تطبيق وسيط إلى Expo

التاريخ: 2026-09-18. المشروع المستهدف: `app`. المصدر: `../reactnative`، ولم تُعدّل ملفاته أثناء النقل.

## النتيجة

تم نقل واجهات وتدفقات التطبيق إلى مشروع Expo SDK 57، وإزالة واجهات قالب Expo التجريبية، وتنظيم التطبيق وفق الأدوار الأربعة. تم اعتماد الخادم الجديد الذي زوّد به صاحب المشروع وفحص Swagger المنشور لمطابقة المسارات والحقول.

النقل البرمجي والتحقق المحلي مكتملان بالحدود الموضحة أدناه. لا يعني نجاح التصدير أن إصدار متجر موقّع قد بُني أو أن جميع الوظائف اختُبرت بحسابات إنتاج.

## 1. هيكل الملفات

- فصل `components` و`api` و`hooks` إلى `merchant` و`sales-employee` و`management-employee` و`delivery-agent` و`shared`.
- فصل controllers الشاشات حسب الدور، مع إعادة استخدام العرض المشترك للمنتجات والطلبات وتفاصيلها.
- قصر `src/app` على صفحات Expo Router والتوجيه والحماية. لم توضع واجهات مشتركة داخل مجلد المسارات.
- إضافة `auth` و`types` و`schemas` و`services` و`config` لتجميع المسؤوليات.
- نقل الخطوط والأصول والألوان، وإعداد اسم التطبيق وسيط وأيقونته وsplash scheme، مع إبقاء معرف الحزمة القديم `com.selling`.

## 2. ما يحصل عليه كل دور

| الدور | الوظائف المنقولة والمربوطة |
| --- | --- |
| Merchant | الرئيسية، المنتجات، تفاصيل المنتج، أسعار قائمة التاجر، السلة وتعديل سعر البيع، إنشاء الطلب، الطلبات وتفاصيلها وتاريخها وأرباح التاجر |
| SalesEmployee | الرئيسية والمنتجات والسلة وإنشاء الطلب ومتابعته، مع فصل واجهة الملخص عن أرباح التاجر |
| ManagementEmployee | قائمة الطلبات وتفاصيلها والتاريخ وتغيير حالة الطلب مع ملاحظة |
| DeliveryAgent | قائمة التوصيل المخصصة، التفاصيل والتاريخ وتحديث الحالة |
| مشترك | الدخول والتسجيل وonboarding، حالة الحساب، الملف الشخصي وتعديله، القائمة، عن التطبيق والتواصل |

المفضلة وسجل الإشعارات واستعادة كلمة المرور لها مسارات وواجهات عدم إتاحة واضحة لأن الخادم الجديد لا يعلن endpoints لها. تفاصيلها في القسم 8.

## 3. المصادقة والحماية

- تعريف موحّد للأدوار الأربعة، مع تحويل الاسم القديم `Sales` إلى `SalesEmployee`.
- رفض الجلسات التي ينقصها التوكن أو معرف المستخدم أو التي تحمل دورًا غير معروف.
- استخدام `Stack.Protected` لحماية كل مساحة عمل، ومنع المستخدم من فتح صفحات دور آخر بالرابط.
- الحسابات Pending/Rejected/Suspended/Blocked/Inactive/Disabled تنتقل إلى صفحة الحالة، مع تحديث الحالة أو تسجيل الخروج.
- حفظ توكن الهاتف باستخدام SecureStore، وفصل معلومات الحساب عنه في AsyncStorage.
- توكن web مؤقت في الذاكرة، وإعادة تحميل الصفحة تتطلب تسجيل الدخول.
- عند الخروج تُمسح السلة وcache الطلبات والجلسة وبيانات التنقل المؤقتة. استجابة 401 قديمة لا تُبطل جلسة أحدث.

## 4. API والخادم الجديد

- تحديث المصدر الافتراضي و`.env.example` إلى `smart-broker-bcd9bzfvagd5f8dx.westus-01.azurewebsites.net/api/`.
- إنشاء Axios client موحد لإضافة Authorization والمهلة وإدارة الخطأ وإلغاء الطلب.
- استخدام RTK Query لتخزين نتائج الخادم مؤقتًا وpagination وإعادة جلب البيانات بعد التعديل.
- توحيد تطبيع envelopes والمنتجات والطلبات مع المحافظة على القيم الصفرية.
- ربط تفاصيل المنتج بـ`GET Product/{id}`، وأسعار التاجر بـ`priceListId` الفعلي.
- ربط تغيير الحالة بـ`POST orders/{id}/status` وبحقلي `targetStatus` و`note`، حسب Swagger.
- عرض البريد الإلكتروني في تعديل الملف الشخصي كحقل للقراءة، لأنه ليس ضمن UpdateUserForm.
- الاعتماد على قائمة الحالات القادمة من الخادم. قيود الانتقالات والصلاحيات الفعلية تبقى في backend.
- حذف البيانات الوهمية التي كانت تسد غياب المنتجات والطلبات والتاريخ والرسوم.

## 5. الشاشات وتجربة الاستخدام

- نقل واجهات الدخول والتسجيل والمنتجات والسلة والشراء والحساب من المشروع القديم وتكييفها مع Expo Router.
- إصلاح حقل الإدخال الذي كان يمنع الكتابة في web بسبب wrapper معطل، وإصلاح تداخل زر الدخول في الشاشات الصغيرة.
- إضافة حالات التحميل والخطأ وعدم وجود بيانات وإعادة المحاولة للقوائم والتفاصيل.
- جلب مناطق التوصيل من الخادم بدل المدن والرسوم المصطنعة.
- التحقق من بيانات العميل والسلة، ومنع النقر المتكرر من إرسال طلبات إنشاء متزامنة.
- ضبط كميات السلة بالمخزون ورفض الأسعار السالبة أو غير المحدودة، وحفظ سعر البيع صفرًا عند اختياره.
- تصحيح عملة ملخص الشراء إلى USD، وعرض الرسوم والإجمالي التقديري دون اعتبار الرسوم المجهولة صفرًا.
- تحميل تفاصيل الطلب/المنتج بالمعرف عند فتح رابط مباشر، والاحتفاظ ببيانات الشاشة الكبيرة داخل الذاكرة.
- توحيد النصوص الرئيسية بالعربية وإزالة وصف متجر الأسنان ومواعيد التوصيل القديمة من صفحة التواصل.

## 6. توافق Expo

- إعداد SDK 57 وReact Native 0.86 وReact 19.2، ومراجعة حزم Expo بأداة توافق الإصدار.
- استبدال التدرجات والأيقونات والتخزين والإشعارات ببدائل تناسب Expo.
- عدم نسخ مشروعات Android/iOS الخاصة بـCLI؛ تُولّد عند البناء من إعدادات Expo.
- إضافة `app.config.ts` لملف Firebase الاختياري وEAS project ID، و`eas.json` لملفات development/preview/production.
- إعداد استقبال إشعار الجهاز وفتحه وتحديث بيانات الطلبات. تسجيل التوكن مع الخادم اختياري وغير مفعّل افتراضيًا لعدم وجود عقد منشور له.
- الاستغناء عن مكتبات أصلية غير مستخدمة بدل نقل جميع dependencies القديمة.

## 7. التحقق

- TypeScript strict: ناجح.
- ESLint: ناجح دون أخطاء أو تحذيرات في المصدر والاختبارات.
- Prettier: ناجح.
- اختبارات الوحدات: 10 اختبارات ناجحة للأدوار والصلاحيات والجلسة والتطبيع والسلة والتوكن واستجابات الفشل و401.
- Expo dependency check: ناجح باستخدام خريطة توافق SDK المحلية.
- تصدير Metro: ناجح لـAndroid وiOS وweb.
- اختبارات المتصفح: 9 اختبارات ناجحة باستخدام Playwright/Chromium؛ تشمل الأدوار الأربعة، وحماية الروابط وصفحات الأدوار، والحساب المعلق، وعدم إرسال استعادة كلمة مرور غير مدعومة، وإنشاء طلب محاكى والتحقق من payload وتفريغ السلة.

اختبارات Playwright تعمل باستخدام API محاكى. لم ننشئ طلبًا أو حسابًا على الخادم الحقيقي. الفحص المباشر كان قراءة Swagger (200) وطلب حالات الطلب دون مصادقة (401).

## 8. الحدود والمتطلبات الخارجية

1. **وظائف لم يوفرها الخادم:** لا يعلن Swagger استعادة كلمة المرور/OTP أو المفضلة أو سجل الإشعارات. تم وقف استدعاء المسارات القديمة، والإبقاء على نقاط التوسعة والخطوات المنقولة مع رسالة عدم إتاحة. تفعيلها يتطلب endpoint وعقد بيانات، وتعديل adapters ثم `config/features.ts`؛ تغيير العلم وحده لا يكفي.
2. **الاختبار الفعلي:** لم تُوفر حسابات لكل دور. لا يصف Swagger أغلب response schemas، لذلك يجب التحقق بحسابات فعلية من الجلسة والأسعار والطلبات وصلاحيات التعديل وانتقالات الحالة.
3. **الإشعارات:** تتطلب Firebase/APNs وتوقيعًا مناسبًا وجهازًا وendpoint لتسجيل التوكن. لا يوجد إثبات إرسال/استقبال push فعلي ضمن هذا التسليم.
4. **البناء الأصلي:** لم يُنتج APK/IPA موقّع، ولم يُجر اختبار على جهاز Android/iPhone. نجاح Metro تحقق لحزم JavaScript والأصول، وليس بديلًا لاختبار native.
5. **تفاصيل المنتج:** البحث والفلاتر في القوائم تعمل على الصفحات المحملة. البحث الشامل يحتاج دعمًا معلنًا من الخادم.
6. **الصيانة:** بعض props في الواجهات القديمة ما زالت تستخدم any؛ أساس العقود الجديدة typed. إعداد i18next موجود لكن الترجمة الكاملة للغتين ليست منجزة.
7. **التواصل:** رقم الدعم من التطبيق القديم محفوظ في config ويجب مراجعته قبل النشر.
8. **توسعات backend:** السحوبات والتقارير والتعيين وإدارة المخزون موجودة في Swagger، لكنها ليست شاشات من التطبيق القديم ولم تُنفّذ كميزات جديدة دون متطلبات عمل إضافية.
