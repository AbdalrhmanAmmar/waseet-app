# تحسين حقول تسجيل الدخول وإنشاء الحساب

واجهة فعلية بمكونات React Native مشتركة، مبنية على هوية التطبيق وخط Tajawal المحلي. حُدّث تسجيل الدخول وخطوات التسجيل الثلاث: بياناتك، التواصل، الأمان.

## تجربة الحقول

- تسمية ثابتة فوق كل حقل، مساحة إدخال تبدأ من ٥٦ نقطة، نص ١٦، وأزرار لمس لا تقل عن ٤٤ نقطة.
- حالات واضحة للتركيز والخطأ والتعطيل، مع مساحة ثابتة للمساعدة وهالة تركيز لا تغيّر حجم الحقل.
- اتجاه عربي للأسماء والعنوان، واتجاه ثابت من اليسار لليمين للبريد والهاتف وكلمات المرور، حتى عند الإظهار والإخفاء.
- إظهار كلمة المرور يعيد التركيز ويحافظ على موضع المؤشر. التحقق يبدأ بعد التفاعل أو محاولة المتابعة، وتُراجع الأخطاء أثناء التصحيح.
- تنقل «التالي» بين الحقول، ثم التركيز على أول حقل خاطئ وتمريره داخل المساحة المتاحة فوق لوحة المفاتيح.
- شريط «التالي / تم» للوحة الهاتف على iOS، ودعم الملء التلقائي باستخدام `autoComplete` دون خصائص متعارضة.

## التسجيل والهاتف

اختيار الدور أصبح شبكة مختصرة للأدوار العامة الأربعة. الاسم الثاني ما زال مطلوبًا، ومدينة التوصيل مطلوبة للمندوب. تحتفظ الخطوات بالقيم عند الرجوع، وتعرض الخطوة الأخيرة ملخصًا وروابط تعديل البيانات الشخصية والتواصل.

كود دولة الهاتف مستقل تمامًا عن بلد الإقامة. قائمة الدول قابلة للبحث بالاسم أو رمز الدولة أو كود الاتصال، مع علم الدولة وعلامة الاختيار.

يبقى الهاتف كما كتبه المستخدم داخل الحقل؛ يحدث التطبيع عند التحقق والإرسال:

- تحويل الأرقام العربية والفارسية وإزالة المسافات والفواصل الشائعة.
- قبول رقم محلي أو رقم دولي يبدأ بـ `+` أو `00` دون تكرار الكود.
- عند اختلاف كود الرقم الدولي عن الكود المختار، يظهر خطأ يطلب اختيار الدولة المناسبة؛ لا يُخمن التطبيق الدولة.
- الاحتفاظ بالأصفار المحلية دون حذف تلقائي، والتحقق من طول إجمالي لا يتجاوز ١٥ رقمًا وحد أدنى ٧ أرقام بعد الكود. هذا تحقق شكلي ولا يثبت ملكية الرقم أو إمكانية الاتصال به.

الحد الأدنى لكلمة المرور ما زال ٨ أحرف، مع مؤشر تحقيق الحد الأدنى وتطابق التأكيد. لا توجد قواعد إضافية غير مطلوبة من الخادم. تُعطل التعديلات والتنقل والإرسال المتكرر أثناء الطلب، وتبقى القيم بعد رفض الخادم. تظهر رسالة الرفض داخل الشاشة ويُمرر التسجيل إليها.

## الملفات الأساسية

- `src/components/auth/AuthField.tsx`: الحقول والأزرار والتنبيهات المشتركة وحالاتها.
- `src/components/auth/AuthFormLayout.tsx`: التمرير والمساحات الآمنة وتجنب لوحة المفاتيح.
- `src/domain/auth-inputs.ts`: تطبيع الهاتف والتحقق منه.
- `src/components/shared/CountryPicker.tsx`: قائمة الدول، مع الحفاظ على الاستعمال الحالي في الملف الشخصي.
- `src/screens/auth/Login` و`src/screens/auth/SignUp`: ربط النماذج والتنقل والطلبات الحالية.

لم تُضف مكتبات أو مسارات API. ما زال تسجيل الدخول يحافظ على معالجة حالات الحساب وتوجيه كل دور، والتسجيل يرسل نفس العقد دون حقل تأكيد كلمة المرور.

## المراجعة

استُخدم [توثيق Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/) و[توثيق TextInput لإصدار React Native 0.86](https://reactnative.dev/docs/0.86/textinput) قبل التنفيذ. اختبارات الواجهة تستخدم API محاكى ولا تنشئ حسابات حقيقية.

اجتازت المراجعة ١١٦ اختبار وحدة و٤١ سيناريو واجهة يشمل النماذج والأدوار وحالات الحساب والملف الشخصي، مع فحوص TypeScript وESLint وتنسيق الملفات المعدلة. اكتمل تصدير Web وiOS وAndroid، وتم تشغيل الواجهات ومراجعة التركيز ولوحة مفاتيح البريد على محاكي iPhone 16e منفصل. تصدير Android لا يعادل اختباره على جهاز فعلي.

شملت المقاسات ٣٢٠ و٣٩٠ و٧٦٨، وارتفاعًا قصيرًا لمحاكاة المساحة المتاحة فوق لوحة المفاتيح. اختبارات كلمة المرور تتحقق من الاتجاه والتركيز والمؤشر، واختبارات الهاتف تتحقق من استقلال الدولة وكود الرقم وإرسال القيمة الدولية مرة واحدة. جرى كذلك اختبار الاحتفاظ بالقيم بعد الرفض وتعطيل التعديلات والإرسال المتكرر أثناء انتظار الرد.
