# قواعد تنظيم المشروع

## اتجاه الاعتماد

`app → screens الخاصة بالدور → hooks الخاصة بالدور → api الخاصة بالدور → api/shared → client`.

الشاشات الخاصة بالدور تعيد استخدام واجهات `screens/shared` والمكونات البصرية في `components/shared`. يمنع نقل منطق الشبكة إلى المسارات، أو استيراد شاشة التاجر مباشرة داخل شاشة مندوب التوصيل. إذا احتاجت ميزتان نفس المنطق، يوضع في `shared` وتحقن فيه الفروق عبر props أو hooks الخاصة بالدور.

## إضافة ميزة

1. عرف نموذج البيانات في `types` ومخطط تحقق النموذج في `schemas` عند الحاجة.
2. ضع endpoint في `api/<role>` إذا كان خاصًا بدور، أو `api/shared` إذا كان متطابقًا. استخدم `baseApi.injectEndpoints` للحفاظ على cache واحدة وtags مشتركة.
3. ضع تنسيق البيانات والـpermissions في hook. لا تكرر تطبيع response في كل شاشة؛ استخدم `api/normalizers.ts`.
4. ابنِ واجهة قابلة لإعادة الاستخدام في `components/shared` أو `screens/shared`، وغلفها بcontroller الدور.
5. أضف مسارًا صغيرًا في `app/(protected)/<role>` ضمن مجموعة الدور المحمية.
6. تحقق من loading/error/empty/retry وعدم تحول خطأ الشبكة إلى نجاح أو بيانات تجريبية. اختبر سلوك الميزة المهم.

## إدارة البيانات

- RTK Query مسؤول عن بيانات الخادم، cache، pagination وإلغاء الطلبات. بيانات القوائم تجمع من صفحات الـinfinite query.
- Redux slice للجلسة فقط؛ بيانات الخادم في RTK Query، ومسودة إنشاء الطلب state محلي للشاشة.
- logout يمسح الجلسة وcache API والبيانات المؤقتة للتنقل، وتختفي مسودة الطلب مع إزالة المسارات المحمية.
- اعتراض 401 مرتبط بالتوكن الحالي لتجنب أن تسجّل استجابة متأخرة خروج مستخدم سجّل الدخول بجلسة جديدة.
- `normalizers.ts` يراعي قيمة صفر باستخدام `??` ويحول envelopes إلى نماذج موحدة. لا يصنع طلبات أو منتجات عند غياب البيانات.
- البحث/فلاتر واجهات القوائم الحالية محلية ضمن الصفحات المحملة. لتوفير بحث شامل يجب إضافة معاملات يدعمها الخادم وتوصيلها بالـquery.

## التنقل

Expo Router هو صاحب شجرة التنقل. `use-screen-props.ts` طبقة انتقال للأسماء القديمة لتقليل إعادة كتابة الواجهات؛ تحفظ بيانات المنتج في ذاكرة محدودة وتضع المعرف فقط في الرابط. تفاصيل المنتج والطلب قادرة على التحميل بالمعرف. لا تضع رموز الجلسة أو بيانات العملاء داخل URL.

الأدوار الأربعة معرفة مرة واحدة في `auth/roles.ts`. `auth/permissions.ts` يجمع صلاحيات العرض؛ `Stack.Protected` يحمي مجموعات الأدوار والحسابات المقيدة. هذه حماية واجهة، وتبقى مصادقة وصلاحيات كل endpoint مسؤولية الخادم.

## Expo والخدمات الأصلية

لا تُنسخ مجلدات Android/iOS من تطبيق CLI. Expo يولدها عند البناء من `app.json` و`app.config.ts`. استُبدلت مكتبات التدرجات والأيقونات والتخزين الآمن والإشعارات بما يلائم إعداد Expo. معرف التطبيق القديم `com.selling` محفوظ للمنصتين، ويجب استخدام بيانات التوقيع الصحيحة عند تحديث نسخة متجر موجودة.

`services/notifications.ts` يفصل إشعارات الجهاز عن سجل إشعارات الحساب؛ السجل غير متاح على الخادم المنشور حاليًا. تغيير `backendFeatures` وحده لا يكفي لتشغيل ميزة: يجب استبدال adapter غير المتاح وتنفيذ اختبارات العقد أولًا.

## صيانة لاحقة

بقيت بعض props من الشاشات المنقولة وطبقة التنقل بنوع `any`؛ العقود الأساسية الجديدة مكتوبة الأنواع والمشروع يعمل بـTypeScript strict. تحسين هذه الأنواع واستخراج بقية النصوص للترجمة ممكن تدريجيًا دون تغيير تقسيم المشروع.

## إنشاء الطلب

- `screens/shared/CreateOrder`: تنسيق النموذج والتحديث والمراجعة والإرسال وحماية المغادرة.
- `components/shared/order-create`: الحقول، اختيار المنتجات والمناطق، محرر عناصر الطلب، الملخص والتنسيق.
- `domain/order-draft.ts`: التحقق وحساب القيم وتحويل المسودة إلى `OrderInput`؛ لا يرسل طلبات شبكة.
- `api/shared/orders.ts`: POST مشترك، مع صلاحية الواجهة `orders.create` للتاجر وموظف المبيعات.
- مساران رفيعان `merchant/create-order` و`sales-employee/create-order`. إجراء «طلب جديد» في التبويبات يفتح الشاشة خارج شريط التبويبات. لا توجد مسارات cart/checkout أو Redux slice للسلة.
- المسودة لا تُخزَّن على القرص. تبقى أثناء الاختيار والمراجعة، وتُمسح بالنجاح أو المغادرة المؤكدة. منع المغادرة يعتمد على `usePreventRemove` من نسخة React Navigation المضمّنة في Expo Router 57.

## لوحة الرئيسية

الرئيسية لا تحمل الكتالوج. `api/shared/home.ts` يقرأ ملخصات الحالات وفترة الرسم، ويتحقق من اكتمال الصفحات قبل التجميع اليومي. `domain/home-orders.ts` مستقل عن المكونات. بيانات الرصيد محفوظة داخل المستخدم مع حالة قدمها؛ `BalanceCard` مشترك بين الرئيسية والحساب، وطلبات تحديث الحساب تمنع التزامن وتتحقق من الجلسة وrequestId.

راجع [تقرير الرئيسية والرصيد](home-dashboard.ar.md) للعقود وحالات الخطأ وحدود البيانات.
